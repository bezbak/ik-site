# AVAT 365 — сайт с админ-панелью

Статический сайт (экспорт из Framer) обёрнут в Django-приложение. Дизайн и вёрстка
остались прежними — Django добавляет базу данных и панель администратора для
контента, который меняется чаще всего: планировки (апартаменты и коттеджи),
документы проекта и вопросы FAQ.

## Что можно редактировать через админку

Открыть `/admin/` и войти под учёткой администратора:

- **Планировки** — тип (апартаменты/коттедж), площадь, спальни/санузлы,
  изображение планировки, галерея фото, описание для страницы планировки,
  текст сообщения для WhatsApp, порядок показа, публиковать или нет.
  Можно добавлять и удалять планировки — карточки на сайте и на страницах
  `/cottages/` и `/apartments/` перестраиваются автоматически.
- **Документы проекта** — название, описание, PDF-файл (или без файла — тогда
  вместо «Смотреть/Скачать» показывается кнопка «Запросить документы»).
- **FAQ** — вопрос, ответ, порядок показа.
- **Контакты сайта** — номер телефона и номер WhatsApp, которые
  используются в кнопках планировок и документов.

Всё остальное содержимое (шапка, инфраструктура, сезоны, галерея, футер)
осталось как в исходном экспорте Framer и правится напрямую в HTML-шаблонах,
если понадобится.

## Локальный запуск

```
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/, админка: http://127.0.0.1:8000/admin/.

Если нужно быстро наполнить базу тестовыми данными, соответствующими
текущему сайту (5 планировок, 3 документа, 7 вопросов FAQ):

```
python manage.py seed_content
```

## Деплой на Railway

1. Создать проект на railway.app, подключить этот репозиторий (Nixpacks сам
   найдёт `requirements.txt` и `Procfile`).
2. Attach a Volume к сервису, точка монтирования, например, `/data`.
   Без этого база и загруженные файлы будут стираться при каждом деплое.
3. Переменные окружения сервиса:
   - `DJANGO_SECRET_KEY` — длинная случайная строка.
   - `DJANGO_DEBUG` = `0`
   - `DJANGO_ALLOWED_HOSTS` = домен(ы) через запятую, например
     `avat365.up.railway.app,avat365.com`
   - `DJANGO_DB_PATH` = `/data/db.sqlite3`
   - `DJANGO_MEDIA_ROOT` = `/data/media`
4. Деплой: `Procfile` при старте прогоняет `migrate`, `collectstatic` и
   поднимает `gunicorn`. После первого деплоя зайти в Railway Shell
   (или `railway run`) и один раз выполнить `python manage.py createsuperuser`.

## Технические детали (для разработчика)

- Framer-экспорт остаётся в JS-бандле сайта и на клиенте **полностью
  перерисовывает** блок планировок, блок FAQ и блок документов из данных,
  зашитых в сборку при экспорте — какой бы HTML туда ни отдал сервер, он
  будет стёрт этим скриптом при загрузке страницы. Поэтому эти три блока
  не рендерятся Django-шаблоном напрямую: вместо этого во `<head>`/конце
  `<body>` лежит небольшой JS-патч (`PROPERTIES_DATA`, `FAQ_DATA`,
  `DOCUMENTS_DATA` — сериализованные Django QuerySet'ы), который подменяет
  автоматически пересозданный Framer-блок на свою версию сразу после
  перерисовки. Так админ-правки реально доходят до посетителя. Не убирайте
  эту подмену и не пытайтесь просто вписать данные прямо в HTML — это уже
  проверено и не работает.
- Статические файлы сайта (`img/`, `assets/`, `video/`, старый `documents/`)
  лежат в `public/` и раздаются WhiteNoise `WHITENOISE_ROOT`-ом прямо в
  корень сайта — поэтому все относительные пути вида `img/photo.jpg`
  продолжают работать без изменений.
- Загруженные через админку файлы (фото планировок, PDF) хранятся в
  `media/` (`MEDIA_ROOT`). На хостингах с "эфемерной" файловой системой
  (где диск сбрасывается при каждом деплое) эту папку нужно подключить как
  постоянный диск/volume — иначе загруженные через админку файлы будут
  пропадать при передеплое.
- База данных по умолчанию — SQLite (`db.sqlite3`), этого достаточно для
  сайта такого размера. Для Postgres — добавить `dj-database-url` и
  прочитать `DATABASE_URL` в `config/settings.py`.
- `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS` — переменные
  окружения для продакшена (по умолчанию берутся безопасные значения для
  разработки).
